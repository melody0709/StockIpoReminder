# 统一还款提醒与银行选择方案

- 状态：已按第 10 节补充契约实施完成，发布基线 0.6.1（2026-11-09）
- 记录日期：2026-11-09（北京时间）
- 版本基线：`Cargo.toml` 当前 `0.5.1`，SQLite schema 当前为 v12
- 范围：将现有「信用卡」页升级为「还款提醒」，统一支持信用卡、房贷、车贷；增加银行下拉选择、本地银行图标和贷款结束状态
- 一句话结论：复用现有按月账期、提醒调度、已还/撤销和通知底座，以统一还款账户模型承载三类账户；贷款必须增加结束还款月或已结清状态，不能直接套用信用卡的无限账期。

---

## 1. 背景与产品结论

### 1.1 用户目标

当前页面只支持信用卡，银行名称需要手工输入。用户还需要记录房贷、车贷等按月还款事项，并希望通过银行下拉和图标降低输入成本、提高列表辨识度。

本产品仍然只是**本地还款提醒和人工确认工具**，不是贷款账本、账单管理器或银行客户端。

### 1.2 已确定的产品决策

1. 保留一个顶层页面，将「信用卡」改名为「还款提醒」，不分别为房贷、车贷增加顶层 Tab。
2. 第一版账户类型固定为：信用卡、房贷、车贷。
3. 三类账户共用：别名、银行、每月还款日、提醒时间、提前提醒、逾期补提醒和启用状态。
4. 房贷、车贷增加「结束还款月（可选）」和「已结清」状态；信用卡不显示这些字段。
5. 银行使用下拉选择。第一版采用现有标准 `ComboBox`，在旁边显示当前银行图标，不开发带搜索功能的自定义弹层。
6. 提供「未指定银行」与「其他银行」。选择「其他银行」后才显示自定义名称输入框。
7. 银行图标在开发期收集并编译进 EXE，不在应用运行时联网搜索、下载或热链。
8. 新增/编辑表单平时收起，点击「新增还款」或「编辑」时展开，保存或取消后收起。
9. 列表操作统一为「本月已还」「撤销已还」；贷款另外提供「已结清」。
10. 第一版不采集贷款本金、利率、月供、账单金额、完整卡号、安全码，也不计算还款计划或利息。

### 1.3 非目标

- 不连接银行、征信机构或第三方支付服务。
- 不验证用户是否真实还款，只记录用户的人工确认。
- 不处理等额本息、等额本金、提前还款违约金或利率调整。
- 不生成贷款 amortization 明细，不展示总利息或剩余本金。
- 不做银行图标运行时下载器、图片搜索服务或远程图标缓存协议。
- 不增加消费贷、经营贷等更多类型；后续如需扩展，应复用本方案的账户类型机制另行评审。

### 2.3 领域模型与账期

当前 `CreditCard` 只有以下业务字段：

```rust

    pub alias: String,
    pub bank: Option<String>,

    pub remind_time: NaiveTime,
    pub lead_days: Vec<u32>,
```

见 `src/finance/credit_card.rs:15-29`。

当前模型没有账户类型、稳定银行 ID、最后账期或结清状态。`CardStatus.next_due` 也是非空日期，计划器会持续向后生成月度账期。因此：

> 房贷和车贷不能只换页面标题后复用现有结构，否则贷款结束后仍会永久生成下一期提醒。

现有可复用规则：

- 月度账期使用 `YYYY-MM`：`src/finance/credit_card.rs:40-57`。
- 短月按月末钳制：`src/finance/credit_card.rs:59-75`。
- 新增账户自动选择本月或下月作为首个跟踪账期：`src/finance/credit_card.rs:77-85`。
- 已还记录以最高已处理账期为高水位，跳过该账期及更早账期。
- 「撤销已还」只允许当前账期或上一账期，不能退回永久可撤销：`src/finance/credit_card.rs:154-171`。
- 到期和逾期提醒只扫描上一月、当月和未来 3 个月：`src/finance/credit_card.rs:312-364`。

## 3. 页面与交互设计

### 3.1 页面结构

保留 `active-page == 5` 和现有导航位置，仅修改显示名称与页面内容：

```text
还款提醒                         [新增还款]
3 项启用 · 最近还款 2026-12-10

[新增/编辑表单：默认收起]

[还款账户卡片]
[还款账户卡片]
```

要求：

1. 导航文案改为「还款提醒」，不新增 Tab，避免进一步挤压健康摘要。
2. 摘要数量单位由「张」改为「项」，逾期文案同步泛化。
3. 页面首次进入且没有编辑目标时，表单收起，把空间留给账户列表。
4. 点击「新增还款」展开空表单；点击某条「编辑」展开并回填该账户。
5. 保存成功或取消后收起；校验失败时保持展开，且不得清空已输入内容。
6. 删除非编辑目标时仍保留当前表单内容，沿用现有防误清空规则。

「结束还款月」留空表示用户未提供结束时间，程序持续按月提醒，直到用户暂停或标记已结清。

第一版不增加「首次还款月」。新增贷款沿用当前账户的首期推断规则：还款日尚未过则跟踪本月，否则跟踪下月。未来才首次还款的贷款可先暂停，后续确有需求再增加首次还款月。

### 3.3 提前提醒交互

将容易输错的 `3,0` 文本框改为：

- 仅当天；
- 提前 1 天 + 当天；
- 提前 3 天 + 当天（默认）；
- 提前 7 天 + 提前 3 天 + 当天；
- 自定义。

选择「自定义」时才显示原始多档输入，并继续执行 0–30 天、最多 4 档、去重排序等现有校验。

表单下方显示下一期实际还款日期预览，尤其是 29/30/31 日遇到短月时，避免用户误解。

### 3.4 银行选择

银行下拉至少包含：

- 未指定银行；
- 工商银行、农业银行、中国银行、建设银行、交通银行、邮储银行；
- 招商银行、中信银行、浦发银行、民生银行、兴业银行、光大银行、华夏银行、平安银行、广发银行；
- 北京银行、上海银行、江苏银行、南京银行、宁波银行、浙商银行；
- 其他银行。

首版清单可以在实施前补充常见城商行，但已发布的内部 `bank_id` 不得因排序或改名而变化。

第一版交互：

```text
[当前银行图标] [招商银行              v]
```

- 图标只表示当前选中的银行，标准下拉项使用文字。
- 「其他银行」使用通用银行图标，并显示自定义名称输入框。
- 「未指定银行」使用中性图标或不显示图标，不能与「其他银行」混为一谈。
- 不在第一版实现 searchable dropdown、远程搜索或下拉项图标弹层。

### 3.5 列表卡片与动作

每张卡片显示：

1. 银行图标或通用 fallback；
2. 别名；
3. 类型标签：信用卡 / 房贷 / 车贷；
4. 银行显示名；
5. 下次还款日期和状态；
6. 提前提醒与提醒时间；
7. 贷款的结束还款月，或「未设置结束月」；
8. 相应动作按钮。

按钮语义：

| 状态 | 主操作 | 其他操作 |
| --- | --- | --- |
| 进行中的启用账户 | 本月已还 | 编辑、删除 |
| 当前/上一账期存在可撤销动作 | 撤销已还 | 按其余状态显示 |
| 暂停账户 | 不显示本月已还 | 编辑、删除；可在编辑中重新启用 |
| 进行中的贷款 | 本月已还 | 已结清、编辑、删除 |
| 已到结束还款月且全部已处理 | 无 | 编辑、删除；显示「还款周期已结束」 |
| 用户手动已结清的贷款 | 无 | 编辑、删除；显示「已结清」 |

「已到结束还款月」不自动宣称用户已经结清，只表示程序不再生成下一期。只有用户点击「已结清」才显示人工确认后的结清状态。

「已结清」需要二次确认，避免误触后永久停止提醒。误操作可通过编辑中的显式「恢复为进行中」修正；恢复时刷新 `rules_changed_at`，不补发恢复前的旧时点。

动作区不能继续简单叠加第五个按钮。实施时应优先将低频动作放入次级菜单或重新排布，并同步重算行高；默认宽度和 800px 紧凑宽度都必须截图验证。

## 4. 领域模型与数据设计

### 4.1 统一账户模型

Rust 领域层建议将 `CreditCard` 泛化为 `PaymentAccount`：

```rust
pub(crate) enum PaymentAccountKind {
    CreditCard,
    Mortgage,
    AutoLoan,
}

pub(crate) struct PaymentAccount {
    pub id: String,
    pub kind: PaymentAccountKind,
    pub alias: String,
    pub bank_id: Option<String>,
    pub bank_name: Option<String>,
    pub due_day: u32,
    pub remind_time: NaiveTime,
    pub lead_days: Vec<u32>,
    pub overdue_enabled: bool,
    pub enabled: bool,
    pub first_tracked_cycle: String,
    pub final_cycle: Option<String>,
    pub closed_at: Option<ChinaDateTime>,
    pub rules_changed_at: ChinaDateTime,
    pub created_at: ChinaDateTime,
    pub updated_at: ChinaDateTime,
}
```

约束：

1. 信用卡的 `final_cycle` 必须为 `None`，信用卡不使用 `closed_at` 表达暂停。
2. 房贷、车贷的 `final_cycle` 为包含端点的最后还款账期。
3. `final_cycle` 若存在，必须不早于 `first_tracked_cycle`。
4. `closed_at` 只用于贷款的人工结清状态；`enabled=false` 仍表示暂停。
5. 已结清、暂停或超过 `final_cycle` 后均不生成新提醒，但三者在 UI 中必须可区分。
6. 下一还款日改为可空；无下一期的账户排在正常待还款账户之后。
7. 已还/撤销仍按 `YYYY-MM` 账期记录，不引入金额和交易流水。

### 4.2 银行注册表

内置银行注册表至少包含：

```text
bank_id       稳定内部 ID，不落下拉序号
display_name  当前显示名称
icon          编译期资源引用
aliases       用于旧数据迁移的精确名称/常见简称
```

建议内部 ID 示例：`icbc`、`abc`、`boc`、`ccb`、`bankcomm`、`psbc`、`cmb`、`citic`、`spdb`、`cmbc`、`cib`、`ceb`、`hxb`、`pingan`、`cgb`。

这些 ID 是程序内部标识，不声称是银行官方代码。发布后只能弃用或增加，不能复用为另一家银行。

显示名解析顺序：

1. 有有效内置 `bank_id`：显示注册表名称与图标。
2. `bank_id == "other"`：显示保留的 `bank_name` 与通用图标。
3. 未指定：显示「未填写银行」。
4. 遇到未来版本或损坏数据中的未知 ID：显示通用图标和保留文本，不阻止账户打开、编辑或提醒。

数据库不存图标路径、远程 URL、ComboBox 索引或图片二进制。

### 4.3 SQLite 迁移策略

按当前基线，目标为下一 schema 版本（预计 v13；若实施前已有其他迁移，则顺延）。

**优先采用低风险的物理表兼容方案：**

- 保留 `credit_cards` 和 `credit_card_actions` 物理表名，避免为改名重写全部外键、动作和台账迁移。
- Rust 领域和 UI 可以改为统一还款账户命名，物理表名留作内部实现细节。
- 在账户表新增 `account_type`、`bank_id`、`final_cycle`、`closed_at` 等列。
- 现有记录全部迁移为 `account_type = "credit_card"`。
- 原 `bank` 文本在迁移中不得直接删除或覆盖。
- 原账户 UUID、已还动作、首个跟踪账期、`rules_changed_at`、创建/更新时间必须保留。
- `finance_shown` 台账必须保留，升级不能导致当前有效提醒重复弹出。

旧银行文本迁移：

| 旧值 | 新 `bank_id` | 原文本处理 |
| --- | --- | --- |
| 空 | `NULL` | 保持未指定 |
| 精确命中内置名称或登记的简称 | 对应内置 ID | 原文本保留用于追溯 |
| 非空但未命中 | `other` | 原文本保留并继续显示 |

银行名称匹配只做明确登记的精确匹配和规范化，不使用模糊猜测，避免把不同银行错误合并。

迁移必须具备事务回滚和重复执行防护，并增加旧库升级测试。

### 4.4 提醒 key 的兼容要求

当前信用卡 `occurrence_key` 已写入 `finance_shown`。如果直接给旧 key 增加类型前缀，升级后可能把同一提醒当成新提醒再次展示。

因此：

1. **现有信用卡 key 格式保持不变**。
2. 新贷款类型使用不会与信用卡冲突的 key 设计。
3. 内存去重、排序和重试身份从单独 `occurrence_key` 泛化为 `(kind, source_id, occurrence_key)`。
4. 持久化已展示台账继续使用现有三元组，不通过清空台账解决冲突。
5. 必须增加「升级前已展示的信用卡提醒，升级后不会重复展示」测试。

### 4.5 修改账户类型

编辑时不允许静默把信用卡直接改成贷款并沿用所有状态，因为两类账户的结束规则不同。

第一版推荐：

- 新增时自由选择类型。
- 编辑已有账户时类型只读；如需更改类型，由用户新建账户后删除旧账户。
- 这样可避免旧已还账期、结束月份和结清状态在类型切换时产生歧义。

若后续允许类型切换，必须单独设计动作历史和 `final_cycle/closed_at` 清理规则，不在本方案中隐式处理。

## 5. 技术实现方案

### 5.1 Slint 表单与列表

- 复用项目已经引入的标准 `ComboBox`，银行模型由 Rust 通过 `VecModel` 提供。
- 下拉索引只用于当次 UI 映射，保存前通过当前银行列表解析为稳定 `bank_id`，并检查列表是否已变化。
- 当前银行图标作为独立 `Image` 属性；列表行模型增加类型、图标、结束状态和结清状态字段。
- 贷款字段使用条件渲染，信用卡编辑时不显示结束还款月。
- 表单增加 `visible/editing` 状态，保存失败不得被后台刷新覆盖。
- 沿用现有 `LineEdit` 宽度约束，窄数字输入不得小于实际文本区需求。
- 新增字段后使用 `min-height` 或明确的折叠布局，不能用固定高度裁掉换行文本。
- 修改 UI 后必须确认 `build.rs` 的 `cargo:rerun-if-changed=ui/main.slint` 仍覆盖构建依赖。

### 5.2 银行图标资源

推荐资源规范：

- 统一为透明背景 PNG，建议 96×96，保证 24–32px 逻辑尺寸和高 DPI 下清晰。
- 图标视觉安全区、留白和背景处理一致，避免不同银行标志大小悬殊。
- 开发期从银行官方或获得授权的素材整理，记录来源、获取日期、许可/商标注意事项和文件哈希。
- 不直接复制来源不明的图标包，不运行时热链银行官网。
- 未知银行和自定义银行使用程序自有的通用图标。
- 图标加载失败只能降级为通用图标，不能影响保存、列表或提醒调度。

资源应通过 Slint 编译期机制嵌入，保持现有单 EXE、便携 ZIP 和 MSI 布局，不新增旁挂资源目录。

### 5.3 调度与状态计算

统一计划器继续复用：

- 自然日还款日；
- 短月钳制；
- 多档提前提醒；
- 到期次日一次补提醒；
- `rules_changed_at` 抑制旧提醒；
- 已还高水位；
- 当前/上一账期撤销窗口；
- 已展示台账和 Runtime 失败重试。

新增终止条件，按以下顺序判断：

1. `closed_at.is_some()`：无下一期，不生成提醒。
2. `!enabled`：不生成提醒，列表显示已暂停。
3. 候选账期晚于 `final_cycle`：无下一期，不生成提醒。
4. 其余情况沿用现有月度计划器。

「本月已还」推进到下一期时，如果下一期超过 `final_cycle`，状态显示「还款周期已结束」，而不是继续生成日期。

### 5.4 通知与路由

- `FinanceKind` 增加房贷和车贷，所有 `match` 必须穷尽处理，禁止落入静默成功的 `_ => Ok(())`。
- 提醒标题、正文、打开按钮和主操作根据账户类型生成。
- Toast 和提醒窗口不得包含完整卡号、金额等新敏感信息；别名和银行继续按现有金融提醒隐私规则脱敏。
- 可引入 `finance:payment:<id>` 作为新路由，同时保留旧 `finance:card:<id>` 的兼容识别。
- 所有类型均打开同一个还款提醒页，并按账户 ID 定位或高亮目标。
- 托盘 Toast、窗口主操作和列表手工确认必须写入同一套动作存储。

## 6. 隐私、安全与可靠性边界

1. 所有账户和动作继续只存本机 SQLite。
2. 不将别名、银行、还款日、贷款结束月写入远程请求。
3. 银行图标查询不根据用户输入实时请求第三方服务。
4. 日志和诊断包只包含账户数量和提醒数量，不包含银行名称、别名或具体日期。
5. 第二通知通道不因为新增贷款类型而自动获得这些正文；如需支持必须另行评审隐私边界。
6. 已结清和删除不同：结清保留历史并停止提醒，删除按现有二次确认清理账户及相关数据。
7. 图标缺失、未知银行 ID 或自定义名称为空属于可降级/可校验问题，不得导致数据库不可读或提醒调度中断。
8. 银行商标只用于识别用户选择的机构，不暗示本程序获得银行授权或与银行连接。

## 7. 测试与验收设计

### 7.1 领域测试

- 三类账户共用的月末钳制、跨月、跨年、提前档位和逾期补提醒。
- 贷款 `final_cycle` 当月仍提醒，下一月不再生成下一期。
- 未填写 `final_cycle` 的贷款继续按月提醒。
- 手动已结清后不再生成提醒；显式恢复后不补发旧时点。
- 暂停与已结清状态互不混淆。
- 最后账期已还后显示「还款周期已结束」。
- 当前/上一账期撤销窗口保持原规则，过旧动作不可撤销。
- 信用卡 `final_cycle/closed_at` 的非法组合被拒绝。
- `final_cycle < first_tracked_cycle` 被拒绝。

### 7.2 存储与迁移测试

- 从当前 v12 旧库升级后，信用卡 UUID、别名、银行文本、还款规则和时间戳不变。
- 旧已还动作、已展示台账和撤销行为不丢失。
- 已知银行名称正确映射，未知名称保留并归入「其他银行」。
- 重复迁移不会重复修改数据，失败时事务回滚。
- 升级前已展示的信用卡提醒在升级后不会重复弹出。
- 新贷款配置、已还、结清、恢复和删除均可持久化。
- 新字段和动作纳入备份指纹。
- 不同类型提醒的 `(kind, source_id, occurrence_key)` 不互相去重。

### 7.3 UI 与通知测试

- 新增/编辑表单展开、保存成功收起、校验失败保留输入。
- 信用卡与贷款切换时只显示适用字段。
- 银行下拉重新排序后仍保存正确 `bank_id`。
- 「其他银行」显示自定义输入，「未指定银行」不要求名称。
- 列表图标、类型标签、结束状态和按钮文案正确。
- 「已结清」有二次确认，恢复为进行中是显式操作。
- 所有新类型的提醒主操作都能落库，不存在静默成功。
- Toast、日志和诊断中不出现别名、银行和贷款日期哨兵值。
- 默认 1180px、800px 紧凑宽度及 1.5× DPI 下截图核对，无按钮截断、文本裁切或健康摘要异常。

- 便携包在断网环境显示全部图标。

## 10. 实施评审补充契约（2026-11-09）

评审确认原方案无需推翻，但实施必须同时遵守以下补充约束：

1. `final_cycle` 不得早于最高已还账期；拒绝缩短到历史之前，不删除或改写已还记录。状态计算同时保留 `next_cycle` 与可空 `next_due`，结束月已过但仍有未处理账期时继续显示该账期，全部处理后才显示「还款周期已结束」。
2. 提醒复合身份 `(kind, source_id, occurrence_key)` 不只用于聚合去重，也贯穿运行时 `in_flight`、失败重试、会话内去重、有效性复核和 UI 丢弃。旧信用卡 `occurrence_key` 原样保留。
3. 三类账户的提醒主操作必须进入同一已还存储；未知类型返回明确错误，禁止 `_ => Ok(())` 静默成功。
4. 「恢复为进行中」定义为 `closed_at=NULL`、`enabled=true`，并刷新 `rules_changed_at` 和 `updated_at`；延长或修改结束月同样刷新规则时间，不补发旧时点。账户类型不可变和已还/撤销窗口均在存储层复核，不只依赖 UI。
5. 复用旧 `bank` 列保存自定义名或保留文本。`other` 的自定义名称 trim 后必填且最多 20 个 Unicode 字符；未知 `bank_id` 编辑时追加保留项，除非用户显式改选，不得回落成未指定银行。
6. 新旧 Toast 路由均携带可用的账户 ID；单条提醒定位目标，多条或混合批次只打开统一页面，不伪造单一目标。
7. 保留当前撤销兼容行为：最高已还动作可以属于上一、当前或未来账期；不能依据计划中「只限当前/上一账期」的概括无意收窄现有行为。
8. v12 升级测试必须显式建立真实 v12 表结构、旧账户、动作和已展示台账，不能仅删除新版本记录模拟。
9. 新字段纳入业务备份指纹；诊断只输出泛化账户数量，不新增银行、别名、结束月或具体日期。
