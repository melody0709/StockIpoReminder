# 还款提醒升级方案：信用贷账户类型、借款与还款金额备注、及月度还款汇总目测

- 状态：方案设计已就绪，待用户评审（2026-11-10）
- 记录日期：2026-11-10（北京时间）
- 版本基线：`Cargo.toml` 当前 `0.6.2`，SQLite schema 当前为 v13
- 对应需求：
  1. 在还款提醒界面新增第 4 种账户类型「信用贷」（消费贷/个人信用贷款）。
  2. 支持填写与备注「借款金额」（总本金）以及具体的「每期还款金额」（月供/当期账单）。
  3. 提供月度还款汇总统计，让用户进入界面能够一目了然“目测”出当月需要还款的总金额、已还金额与待还金额。
- 核心原则：**完全本地离线存储，零网络隐私边界，向下平滑兼容**。

---

## 1. 现状剖析与用户痛点

### 1.1 当前实现分析
在现有的 `0.6.2` 版本中，还款提醒覆盖了「信用卡」「房贷」「车贷」三种类型：
- **账户模型**：仅包含别名、银行标识、还款日、提醒时间、提前天数、结束还款月及结清状态。
- **免责文案**：原表单底部明确注明：“只保存别名、银行和日期；请勿填写贷款金额、利率、完整卡号、安全码或账单金额”。
- **痛点 1（缺少信用贷）**：现代个人与家庭负债结构中，除按揭房贷与汽车金融外，各类正规商业银行的个人消费贷/信用贷（如招行闪电贷、建行快贷、工行融e借、中行E贷等）极其普遍，现有三种类型无法准确归类。
- **痛点 2（无金额信息，无法宏观掌握现金流）**：用户不仅需要知道“哪天该还哪笔钱”，更需要知道“这个月总共要备多少钱还款”。目前用户看完整张列表，必须自己心算或掏出计算器逐项相加，无法直观“目测”本月还款总盘子。
- **痛点 3（借款本金无法备忘）**：贷款类往往有固定的借款总额（如信用贷借款 10 万元、车贷 15 万元），若无法备注，用户经常遗忘贷款的原始规模。

## 2. 核心架构与模型设计

### 2.1 账户类型扩展：新增「信用贷」

在领域层与交互层将账户类型扩展为 4 种：
1. **信用卡** (`credit_card`)：循环信用，每期账单波动或可选备注。
2. **房贷** (`mortgage`)：长期抵押贷款，通常每期固定月供。
3. **车贷** (`auto_loan`)：分期汽车金融，固定月供。
4. **信用贷** (`credit_loan`，**新增**)：个人消费信贷/信用贷款，固定期限与月供。

#### 贷款类聚合定义
房贷、车贷、信用贷统称为**贷款类（Loans）**：
```rust
impl PaymentAccountKind {
    pub(crate) fn is_loan(self) -> bool {
        matches!(self, Self::Mortgage | Self::AutoLoan | Self::CreditLoan)
    }
}
```
贷款类具备共同特性：
- 支持选填「结束还款月」（如 `2027-06`），到期自动终止提醒；
- 支持「标记已结清」与「恢复进行中」生命周期流转；
- 共同支持「借款总额」与「每期月供」字段。

---

### 2.2 金额双字段模型设计

为清晰区分“借了多少”与“每月还多少”，避免将借款本金误算入月度支出的荒谬计算，设计两个精细化字段：

| 字段名称 | 类型 | 适用类型 | 含义与业务用途 | 界面输入提示 |
| :--- | :--- | :--- | :--- | :--- |
| **`amount`** | `Option<f64>` | 所有类型（选填） | **每期还款额 / 月供 / 当期还款额**<br>核心计算字段：用于汇总本月应还、待还与已还金额。 | 信用卡：`本期金额，如 3200`<br>贷款类：`每期还款，如 5800` |
| **`total_amount`** | `Option<f64>` | 仅贷款类（选填） | **借款总额 / 贷款本金**<br>备忘展示字段：用于记录该贷款总规模，在卡片上展示，不参与月度累加。 | 贷款类：`借款总额，如 100000` |

#### 数据校验规则
- 金额必须是非负浮点数（`amount >= 0.0`，`total_amount >= 0.0`），空字符串或全空格转为 `None`。
- 上限保护：单笔上限限制为 `100_000_000.0`（一亿元），防止非法超大数字溢出。
- 精度处理：存储为浮点，界面格式化统一保留 2 位小数并做千分位分隔（如 `¥5,800.00`），输入支持整数或小数（如 `5800` 或 `5800.5`）。

## 4. 界面交互与月度还款“目测”汇总系统

### 4.1 顶部汇总栏升级（一秒目测现金流）

目前列表顶部的 `credit-summary` 只显示“X 项启用 · 最近还款 YYYY-MM-DD”。
优化后，系统在刷新时计算当前月度（以系统当前时间的年月为基准）：
- **本月应还总额 (`total_due_amount`)**：本月生效且未结清的账户金额总和。
- **本月待还总额 (`total_pending_amount`)**：本月尚未处理的账户金额总和。
- **本月已还总额 (`total_paid_amount`)**：本月已被标记为“本期已还”的账户金额总和。
- **有金额账户数 (`accounts_with_amount`)** 与 **未填金额账户数 (`accounts_without_amount`)**。

#### 汇总展示策略
1. **全部或部分账户填写了金额**：
   - 存在待还项目：
     `本月待还 ¥12,500.00 · 已还 ¥5,800.00 (本月应还 ¥18,300.00 · 4 项启用)`
   - 若存在未填金额的项目，贴心提示：
     `本月待还 ¥12,500.00 (另 1 项未填金额) · 已还 ¥5,800.00`
   - 当月已全部还清：
     `本月已全部结清 ¥18,300.00 · 4 项已还`
2. **没有任何账户填写金额**：
   - 自动优雅降级，保持原有格式：
     `4 项启用 · 最近还款 2026-12-05`
3. 视觉呈现：
   - 「待还」金额采用明亮天蓝/琥珀金加粗呈现，一眼聚焦；
   - 「已还」采用淡青绿，传达安全结清感。

## 5. 边界与异常情况处理

1. **跨月与到期贷款**：
   - 若某笔贷款的 `final_cycle` 为 `2026-10`，当时间进入 `2026-11` 且旧账期均已结清，该账户自动不计入本月应还与待还中。
2. **已结清（`closed_at.is_some()`）与已暂停（`enabled == false`）**：
   - 自动排除在当月汇总之外，避免虚假抬高待还金额。
3. **未设置金额与混合情况**：
   - 允许部分账户设置金额、部分账户留空。汇总文案明确提示“另 X 项未填金额”，确保数字严谨、不产生“所有贷款加起来才这点钱”的错觉。
4. **数字解析容错**：
   - 支持用户输入带逗号的格式（如 `5,800` 自动清理为 `5800`），支持非法字符拦截并红字提示。
