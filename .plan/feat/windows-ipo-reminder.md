- 当前应用版本：0.3.1，以 Cargo.toml 为唯一版本事实来源

## 0. 当前结论

Stock IPO Reminder 已完成从 C#、WPF 到 Rust、Slint 的正式迁移。当前仓库的正式运行载荷是单个 StockIpoReminder.exe，发布形式为 x64 MSI 和便携 ZIP，不依赖 .NET Runtime。

0.3.1 已具备可运行的核心业务闭环：

- 四来源有界候选采集、多来源裁决，以及只保存标题、来源、发布时间和官方 URL 的正式公告元数据检索。
- SQLite 持久化、逐只确认与撤销、关键变化后重新确认。
- 四态同步结论、来源计数审计、来源健康和持久化退避。
- 06:00–22:00 自动同步窗口、前夜和 08:00 定点核验、错过补做与确定性抖动。
- 持久化提醒 Outbox、跨重启 lease 恢复，以及窗口可见、未最小化并与显示器工作区相交后才完成投递。
- 独立置顶提醒窗、同轮聚合、托盘常驻、第二次启动唤醒已有实例，以及 Explorer 重建后重新注册图标。
- 原生 WinRT Windows Toast、稳定 AUMID、MSI 开始菜单快捷方式绑定，以及 Toast 失败后的托盘气泡回退。
- 专用提醒窗、Windows Toast、托盘气泡回退、声音和任务栏闪烁的分通道自检。
- 用户明确确认已申购后，按已知公告日期安排中签查询和缴款资金提醒；撤销确认会取消这些提醒并恢复申购提醒。
- 用户明确确认已申购后，按已知上市日期安排上市日 08:30 本地提醒；不读取持仓、不跟踪价格或收益。
- 今日任务与未来 60 天支持文本、市场和状态组合筛选，并使用 Slint ListView 虚拟化任务卡片。
- 设置页可从当前用户进程启动安全 MSI 卸载；默认保留数据，可选清理必须精确确认且只允许当前用户默认数据目录。
- 每日备份、日志保留、运维健康、诊断 ZIP 和异常退出报告。
- Windows Time 服务检查、同 EXE Watchdog、崩溃循环限制、数据库迁移前备份。
- 主窗口和托盘先呈现，数据库备份、迁移、完整性检查与必要压缩在后台完成；就绪前数据库操作有统一门禁。
- 设置页提供当前本地缓存/数据目录入口；提醒通道卡片为完整测试矩阵预留自适应高度，不再截断底部测试项。
- x64 MSI、便携 ZIP、发布布局、Windows smoke、发布审计和联网内存测量。
- 可选 Authenticode/RFC 3161 签名构建、detached CMS 更新清单、签名证书固定、MSI 安装版安全自动更新和短生命周期更新 helper。
- 用户明确同意后可发送二次脱敏的受控 Watchdog 崩溃报告；默认关闭，接收地址和隐私政策必须同时配置为无凭据 HTTPS。
- 可选企业微信、钉钉、飞书或 PushPlus 第二通知通道；默认关闭，凭据用 Windows DPAPI 当前用户范围加密，并由独立持久化 Outbox、租约恢复、重试和小时配额控制发送。

### 0.1 产品减重决策（2026-08-26）

- 新股提醒的核心字段以 Eastmoney、SSE、CNINFO、BSE 的结构化数据为准，包括代码、简称、申购代码、申购日期、发行价格、申购上限、市值/资金要求，以及上游公布后的中签、缴款和上市日期。字段尚未公布时保持“待公布”，由后续同步补齐，不通过 PDF 或 OCR 猜测。
- OCR 永久排除出产品范围。扫描件、加密文件和异常版式不做图像识别或版面理解；用户需要核对时直接打开官方公告链接。
- 不再研究 PDF 按页/按对象解析、外部低内存解析器或 OCR 引擎。
- P0 已停止自动下载和解析公告 PDF，并移除 `lopdf`、PDF Worker、对应 Job Object 与解析状态链路；当前只保留公告标题、来源、发布时间和官方 URL，允许用户用浏览器手动核对原文。
- 当前版本不再产生新的 `AnnouncementVerified` 状态或本地公告文件；旧数据库中的历史状态、公告记录和已有 PDF 继续兼容读取，但不会自动删除。
- 退役 PDF 自动处理不得削弱四来源采集、数量审计、来源健康、冲突提示、缺失字段保留和“来源不完整时不得宣称今日无新股”等现有可靠性边界。

### 0.2 候选数据源减负决策（2026-08-26）

- Eastmoney 的 `RPTA_APP_IPOAPPLY` 是历史累计表。此前无过滤请求固定第一页 500 条，却用全历史 `result.count=5622` 与本页明细数比较，造成长期 Warning；500 条全部通过解析，问题属于查询范围和分页审计语义，不是解析丢数。
- Eastmoney 保留为全市场候选发现来源，不下载全历史。查询改为申购日在过去 60 天至未来 60 天，只请求代码、简称、市场、申购日期、发行状态、申购代码、价格、单位、上限、市值要求、中签、缴款和上市日期等实际使用字段，并按过滤后的页数读取。
- SSE 改用其官方“新股发行一览”页面自身的 `isIssue=1`、`pageHelp.cacheSize=1` 查询语义，不再读取全历史发行记录。BSE 使用页面接口已经支持的 `startTime/endTime` 限定同一 120 天窗口。CNINFO 当前只提供小型近期 IPO 结果集，三个公告源也已经按单只股票和短日期窗查询，因此保持现状。
- Eastmoney、SSE、BSE 的有界查询最多读取 5 页。超过上限时继续使用已解析候选，但声明数与实际明细数不一致会使来源进入 Warning，不能参与“完整覆盖”结论；Eastmoney 明确的空窗口响应按 0 条健康结果处理。
- 本次减负不改变来源优先级：交易所/CNINFO 结构化字段仍为 200，Eastmoney 为 100；不把第三方聚合结果置于官方来源之上，也不移除全市场发现兜底。

仍须避免以下误判：

- Windows Toast 主路径已经实现；当前只要求在实际安装环境验证用户启用的 Toast 或气泡回退一次，不再要求覆盖通知中心、勿扰、专注助手和所有系统策略组合。便携版没有 MSI 快捷方式注册时允许明确降级到托盘气泡。
- 专用提醒窗已实现；当前 Windows 11 上真实触发一次属于必做，多屏和混合 DPI 只在实际使用这些环境时验收。
- Watchdog 是同 EXE 的用户态监督进程，不是 Windows Service；单次恢复、崩溃循环上限和监督进程被结束后的主进程行为已有矩阵证据。同时结束监督进程和主程序后无法继续恢复属于接受的产品边界，注销和关机不再追加专项矩阵。
- MSI 不直接修改用户数据库。当前保护是在新版本第一次打开旧数据库、执行 schema 迁移之前创建完整性校验备份；它不是 MSI deferred custom action。
- Windows 10、RDP 和多屏混合缩放没有形成正式支持证据，因此当前只声明 Windows 11 x64 验证范围；Explorer 自动重启恢复已由用户确认闭环。MSI 只补最小安装、升级、保留数据卸载和明确清理，不做完整失败排列。
- Authenticode、签名更新清单和自动更新主路径已经实现，但当前 0.3.1 基线未接入正式 CA 证书和 HTTPS 稳定版源，发布清单明确为 `signed=false`，应用内更新保持关闭；这些只在正式公开分发或上线自动更新时转为必须。
- 崩溃报告客户端主路径已经实现，但当前 0.3.1 发布未配置接收服务和隐私政策，release manifest 中两个地址均为 null，上传保持关闭；只有决定运营正式服务时才补外部接入。
- 第二通知通道是用户配置的本地客户端补充投递，不是服务端推送或多设备同步；只对用户实际启用的服务商做真实验收，邮件、短信、任意自建 Webhook、企业代理和自定义 CA 仍暂停。
- 旧 PDF Worker 的资源边界和内存报告仅作为历史基线保留；当前源码已移除 Worker 和 `lopdf`，同步不再创建 PDF 子进程、下载临时文件或新增公告 PDF。

## 2. 状态标记

- **已实现**：源码存在完整主路径，并有自动化测试、发布脚本或当前版本运行证据。
- **已实现，证据待补**：源码主路径完整，但特定 Windows 环境或真实交互场景尚未形成版本化报告。
- **已实现，外部接入待补**：源码、构建和离线验证主路径完整，但正式凭据、线上服务或发布环境尚未接入，不能等同于正式上线验收。
- **部分实现**：已有基础能力，但语义、交互、可靠性或验证范围仍低于目标。
- **未实现**：当前源码没有对应主路径，保留为后续研究项。
- **历史替代**：旧方案被新的技术决策替代，不应照搬旧代码，但原产品目的继续保留。

后续优先级统一使用以下定义：

- **必须**：直接影响当前 Windows 11 上数据能否获取、提醒能否准时显示、恢复后是否漏提醒，以及安装/卸载是否安全；未完成前不能宣称日常使用闭环。
- **优化**：已有自动化证据且不影响核心提醒，可在出现真实问题或顺手维护时处理，不阻塞当前版本。
- **条件项**：只有正式公开分发、启用某个默认关闭功能或承诺额外平台支持时才转为必须。
- **停止**：极端矩阵、未开发扩展或已经明确排除的重型能力，不再投入当前阶段。

### 4.2 进程与线程

- 正常启动先运行轻量 Watchdog 监督进程，再启动同 EXE 的主程序子进程。
- Watchdog 持有独立监督 Mutex；主程序持有数据目录级应用 Mutex。
- 同一数据目录再次启动时不会创建第二套 UI；它会向已有托盘消息窗口广播数据目录专属激活消息，并在主窗口实际可见后记录确认事件。
- 主程序使用 Slint 事件循环；隐藏最后一个窗口不会退出。
- Runtime 在线程 stock-ipo-runtime 中处理同步、投递、健康和维护。
- 第二通知自动批次由 Runtime 线程从独立 Outbox 租赁并发送；用户主动“发送测试”在短生命周期后台线程执行，二者在联网前共享小时配额预留。
- 托盘在线程 stock-ipo-native-tray 中处理菜单、气泡和 Windows 广播。
- 更新检查和下载在后台线程执行，不阻塞 Slint 事件循环。
- 用户明确安装后复制同 EXE 为短生命周期更新 helper；helper 等待主程序退出，再调用 Windows Installer。
- 自测试、部署 helper、更新 helper 和显式 no-watchdog 模式不会再创建监督层；同步链路不再创建 PDF Worker 子进程。

## 5. 关键业务不变量

### 5.1 确认语义

- 每只股票独立确认，禁止一键确认同日全部股票。
- 只有任务所列申购日当天可以确认。
- 显示窗口、发送气泡、关闭窗口、稍后处理、锁屏、休眠或程序重启都不等于已申购。
- 确认只代表用户在本程序中的人工记录，不代表券商已受理。
- 只有用户明确确认已申购后，才允许创建中签查询和缴款资金提醒；程序不得根据时间或页面状态自动推断已申购。
- 撤销确认必须事务性取消中签/缴款提醒，并恢复仍适用的申购提醒。
- 关键字段变化后旧确认必须失效并进入待复核。
- 撤销确认、生命周期恢复和提醒重排必须处于同一事务。

### 5.2 数据可靠性

- 任何单一来源失败都不能清空其他来源已经发现的任务。
- 只有启用市场的必要来源完整成功，且数量审计一致，才允许显示“今日无新股”。
- 上游缺失可选字段不得自动清空已有可信值。
- 公告元数据的检索地址和保存的原文 URL 必须继续遵守官方域名白名单；程序不得主动请求 URL 指向的 PDF 正文。
- 扫描、加密、超限或异常版式公告不得触发 OCR；只保留官方链接供用户自行打开。
- 不得重新引入 PDF Worker、自动 PDF 下载或新的公告正文解析器。
- 版本迁移前备份失败时不得继续 schema 迁移。
- 已提交的版本标记、DPAPI 凭据和崩溃上传状态不得通过“先删旧文件再重命名”更新；替换必须请求 Windows 写穿语义。

### 5.3 提醒可靠性

- Outbox 是提醒事实来源，UI channel 只是投递通道。
- 旧事件版本的 Pending、Leased 和 Failed 提醒必须取消。
- 只有持有有效 lease 的投递才能完成或失败。
- 专用提醒窗只有在原生窗口可见、未最小化且与显示器工作区相交后，才可把对应 lease 标记为完成。
- 单股多个到期提醒可合并显示，但不得合并确认语义。
- 程序恢复时不得重新创建整天已经过期的申购提醒；同股多个过期等级只保留最新到期等级。
- 投递失败必须采用有界退避并进入健康摘要，不能形成紧密失败循环或静默丢失。
- 强杀、租约过期和数据库重开后不得丢失尚未完成的提醒。

### 5.4 产品边界

- 不保存券商账号、密码、验证码、持仓、市值、资金或交易凭据。
- 不读取可申购额度。
- 不调用券商下单接口。
- 不验证委托是否成功。
- 不读取或推断是否中签，也不判断是否已经完成缴款。
- 中签日 18:00、缴款日 08:30/14:00 只是本地提示点，不代表交易所、主承销商或券商截止时间。
- 不做收益预测。
- 不绕过登录、验证码、WAF 或访问控制。
- 不把第三方开源项目、AKShare 或 Tushare 作为唯一生产来源。

### 5.5 安全卸载与数据删除

- 普通卸载默认保留数据库、设置、公告缓存、日志和备份。
- 应用内卸载只接受由稳定 UpgradeCode `A007780A-97A8-483E-A532-F336649EC5BB` 枚举到的当前已安装 ProductCode，不允许传入任意 MSI 标识。
- 临时 helper 以发起操作的当前用户身份运行，等待主程序完全退出后再调用 `msiexec /x ... /passive /norestart`。
- 只有用户勾选数据清理并准确输入 `删除当前用户数据` 时，才允许进入清理分支；Rust helper 会再次独立校验短语。
- 清理目标必须精确等于当前用户 `%LocalAppData%\StockIpoReminder`，拒绝自定义目录、其他用户目录和包含 `..` 的路径，也不枚举用户配置文件。
- 只有 Windows Installer 返回成功或“成功但需要重启”后才删除数据；取消、UAC 拒绝、超时或其他失败必须完整保留数据。
- 便携版没有 MSI 注册时不启用应用内卸载入口，用户退出后自行删除便携文件。

### 5.6 签名发布与自动更新

- 未同时编译 HTTPS stable 清单 URL 和合法 64 位证书 SHA-256 指纹时，应用内更新必须保持关闭。
- 便携版和未注册的 MSI 载荷不得启用应用内安装；不得把便携版静默转换为安装版。
- detached CMS 清单签名和 MSI Authenticode 必须固定到同一证书 SHA-256；产品、stable 通道、严格 `x.y.z` 版本、最低 Windows Build、大小和哈希必须全部通过。
- 只允许升级到高于当前 `CARGO_PKG_VERSION` 的版本，不接受降级、同版本、预发布或非三段数字版本。
- 下载的 MSI 只允许位于当前数据根目录的 `temp\updates`，安装 helper 必须再次复核路径、SHA-256、系统信任和签名证书指纹。
- 自动更新只能自动检查；下载和安装必须由用户明确点击。任何下载、CMS、哈希、证书、Windows Installer 或退出等待失败都不得启动或继续安装。
- 临时自签名测试根的放宽只存在于 `--update-bundle-self-test` 诊断命令；生产检查、下载和安装路径始终要求 Windows 系统信任。

### 5.7 第二通知通道安全与投递边界

- 第二通知通道默认关闭，只是本地桌面提醒的补充；远程发送失败不得改变或阻断桌面提醒的完成、确认和撤销语义。
- 企业微信、钉钉和飞书只接受对应官方主机与固定路径的无凭据 HTTPS Webhook；PushPlus 只接受 token，并固定发送到官方 HTTPS 端点。
- Webhook 和 token 必须用 Windows DPAPI 当前用户范围加密；不得进入 SQLite、日志、诊断 ZIP、数据库备份、命令行、环境变量或发布清单。
- 自动批次和用户主动测试必须在联网前统一预留小时配额；租约、失败退避、最多尝试次数和历史清理都必须持久化且有界。
- 关闭通道或切换服务商时，旧服务商尚未完成的队列必须取消，不得把旧消息投递到新目标。
- 当前边界不包含邮件、短信、任意自建 Webhook、企业代理、自定义 CA、客户端证书、端到端加密、服务端推送或多设备同步。

## 6. 当前实现细节

### 6.1 同步与来源健康

自动同步调度包含：

- 06:00 之前推迟到窗口开始。
- 22:00 之后推迟到下一天窗口开始。
- 申购日前一日 20:00 固定核验。
- 申购日 08:00 固定核验。
- 如果启动或恢复时已经错过固定点，则立即补做。
- 普通日期轮询加入 0–90 秒确定性抖动。
- 申购日轮询加入 0–20 秒确定性抖动。
- 普通日期和申购日间隔分别配置，默认 30/10 分钟。

同步结论：

- Unknown：尚无足够结论。
- HealthyNonempty：必要来源完整，得到有效任务。
- HealthyEmpty：必要来源完整且确认没有任务。
- DegradedCached：来源不完整或审计异常，继续使用缓存。

来源退避：

- 429/503 优先采用 Retry-After。
- 无有效服务端指示时采用 1、2、4、8、15、30 分钟本地退避。
- 本地退避带持久化抖动。
- 退避 10 分钟后允许低频健康探测，最长每 30 分钟一次。
- 探测只判断站点可达性，不绕过或提前清除 API 退避。

### 6.2 提醒与 Outbox

未确认申购时，提醒计划覆盖前一日、早间、券商受理、官方开盘、小时、上午边界、下午恢复、临近截止和最终截止。

申购后提醒：

- 设置 `post_apply_reminders_enabled` 默认开启，并可在设置页关闭。
- 设置 `listing_reminders_enabled` 默认开启，上市日提醒可独立关闭。
- 只有用户明确确认已申购后才安排；不会读取券商账户或根据时间自动推断。
- 已知中签结果公告日时，在当天 18:00 提醒用户自行查询中签结果。
- 已知缴款日时，在当天 08:30 和 14:00 提醒用户自行准备或复核资金。
- 已知上市日时，在当天 08:30 提醒用户核对交易所公告和行情软件；不读取持仓、不跟踪价格或收益，也不保证证券当日一定可正常交易。
- 撤销申购确认会在同一事务中取消后续中签、缴款和上市提醒并恢复申购提醒。
- 全量重排会回看最近 60 天，以便覆盖已经申购但仍处于中签、缴款或上市阶段的事件。
- 规划显式使用调用方传入的当前时间；已经过去的中签、缴款和上市日期不再创建提醒，当前日期只保留尚未到达的时间点。
- 正式公告解析支持“中签结果公告日”“网上投资者缴款日”“网上缴款日及截止时间”“缴款日期”等字段标签；日期未知时不猜测。

当前专用提醒窗：

- 独立于主窗口。
- 置顶显示。
- Windows 下使用 WS_EX_NOACTIVATE 和 WS_EX_TOOLWINDOW。
- 尽量定位到当前工作区右下角。
- 提供打开详情、单股二次确认和稍后处理。
- 多股同轮到期时只提供打开今日任务，不提供批量确认。

Outbox v7：

- message 字段保存 DataChanged 或复核原因。
- 事件版本变化会取消旧版本残留。
- 查询严格关联当前事件版本。
- lease 过期可跨进程重领。
- 到期判断使用 `<= now`；恢复后同一股票较低的过期申购提醒折叠到最新到期等级，旧的未确认任务不会重新创建整天的历史提醒。
- UI 显示专用提醒窗后延迟执行原生可见性检查；只有窗口可见、未最小化且与显示器工作区相交时才完成投递，否则记录失败并保留重试。
- 本地显示失败按 1、5、15、30 分钟退避；健康摘要记录失败数量、最早失败时间和最近脱敏错误，持续 15 分钟后由 Warning 升级为 Failed。
- 跨数据库重开测试覆盖入队、租约中、过期重领、显示完成和确认取消。

### 6.3 运维、备份与诊断

- Watchdog/单实例建立后立即创建主窗口和托盘；数据库升级备份、initialize、空间回收和 integrity_check 在 runtime 后台线程执行。
- 数据库未就绪时，UI 只读取内存快照；设置保存、确认、撤销、人工覆盖、第二通知测试和诊断导出返回“本地数据库仍在后台初始化”，不会以默认设置覆盖真实配置。
- SQLite 在线备份从每 128 页暂停 50 ms 调整为每 1,024 页暂停 1 ms。57,025 页旧库原参数会产生约 22.25 秒固定等待，新参数的固定让出时间低于 60 ms。
- 维护每小时独立运行，不依赖同步成功。
- 每日备份使用 SQLite 在线备份 API。
- 每次备份使用唯一临时文件，写入后执行 integrity_check，并在读写句柄上执行 `sync_all`。
- 关闭目标连接后原子提交；提交前中断会清理本轮临时文件并保留已经存在的备份。
- 失败时清理临时文件。
- 默认保留最近 7 份备份。
- 日志按日期命名，单日达到大小上限后分段，保留 14 天。
- 维护、备份和日志保留失败写入 operation_health。
- 同步运行继续记录来源、时间、结果、条数、结构指纹、响应哈希和脱敏错误，但不再持久化接口正文；migration v9 清除旧正文，空闲页达到总页数四分之一时执行 VACUUM。
- 233,574,400 bytes 的真实 schema v8 数据库副本迁移实测：UI/托盘 17 ms 呈现，备份约 0.58 秒完成，空间回收约 1.19 秒完成，最终数据库 782,336 bytes、191 页、0 空闲页。

版本升级保护：

- application-version.txt 记录最近一次成功初始化数据库的应用版本，并通过 Windows `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` 替换。
- 发现数据库 schema 低于当前 `LATEST_SCHEMA_VERSION` 或无法安全识别时，先创建完整备份；单纯应用版本变化不触发重复备份。
- 只有 initialize 和 integrity_check 都成功后才更新版本标记。
- 这同时保护 MSI 与便携版首次运行，不依赖安装目录。

诊断 ZIP schema v4 包含：

- 应用版本和 schema migration 版本。
- SQLite 完整性。
- 最新类型化同步结论。
- 最近同步运行。
- 来源健康与运维健康。
- 本地提醒 Outbox 和第二通知 Outbox 状态摘要。
- 最近提醒日志。
- 最近 Watchdog 崩溃报告。
- `windowsToast`：进程 AUMID、ToastNotifier 创建、NotificationSetting、开始菜单快捷方式与 AUMID 匹配、SHQueryUserNotificationState。
- 脱敏后的近期日志。

诊断 ZIP 不包含：

- 主数据库。
- 公告全文。
- Cookie、Authorization。
- URL 查询参数。
- 用户绝对路径。
- 第二通知通道 Webhook、token 或 DPAPI 加密文件内容。

### 6.4 Windows 集成与恢复

Windows 通知：

- 进程使用稳定 AUMID `StockIpoReminder.Desktop`。
- MSI 开始菜单快捷方式写入相同的 `System.AppUserModel.ID`。
- 主路径通过 WinRT `Windows.UI.Notifications` 创建 Toast；标题和正文会做 XML 转义及长度限制。
- Toast 不可用时自动回退到 Shell_NotifyIcon 托盘气泡，并设置 `NIIF_RESPECT_QUIET_TIME`。
- 便携版不会伪装成已经完成 MSI 快捷方式注册；Toast 不满足平台条件时明确降级。
- 设置页把专用提醒窗、Windows Toast、气泡回退、声音和任务栏闪烁拆成独立测试。

Windows 恢复 smoke schema v10：

- 先执行 NIM_DELETE 模拟 Explorer 丢失托盘图标，再发送真实 `TaskbarCreated` 注册消息，要求 NIM_ADD 成功 1 次且失败 0 次。
- 发送 `WM_POWERBROADCAST / PBT_APMRESUMEAUTOMATIC`、`WM_WTSSESSION_CHANGE / WTS_SESSION_UNLOCK` 和两轮 `WM_TIMECHANGE`。
- 验证防抖接受 2 次、抑制 2 次、Runtime 恢复回调 2 次；smoke 模式不执行真实联网同步，生产路径不变。
- 自动化证据覆盖消息处理和防抖逻辑；用户另已确认真实 Explorer 进程重启后托盘恢复可用。物理睡眠/锁屏恢复需要完成一次核心验收，RDP 只在实际使用时再测。

第二次启动：

- 应用 Mutex 和激活消息均按数据目录隔离。
- 检测到已有监督进程或主程序时，等待启动竞态并广播激活消息。
- 已有实例在 Slint 事件循环中显示并重绘主窗口，随后用原生可见性检查写入确认日志。

当前 Windows 消息路径覆盖：

- 休眠或待机恢复。
- Windows 会话解锁。
- 系统时间变化。
- 网络从不可用恢复为可用。
- Explorer 任务栏重建。

恢复事件会防抖，并触发投递检查、时间检查和一次同步请求。

W32Time：

- 使用服务控制管理器读取 W32Time 状态。
- 服务未运行时至少显示 Warning。
- 服务状态读取失败时显示明确警告。
- 网络时间偏差超过 5 分钟仍优先显示 Failed。

Watchdog：

- 子进程退出码 0 视为正常退出，不重启。
- 非零退出视为异常退出。
- 每次异常写入 diagnostics/crashes 下的 JSON。
- 在 10 分钟窗口内按 2、10、30 秒最多重启 3 次。
- 第 4 次异常停止重启，避免崩溃循环。
- 当前矩阵已验证单次强杀恢复、连续四次崩溃停止重启，以及监督进程被强制结束后主进程继续正常运行。

### 6.5 安装与卸载

- MSI 继续使用 per-machine、Major Upgrade、可选安装目录和稳定 UpgradeCode。
- 设置页启动卸载前先用 Windows Installer API 查询本产品当前 ProductCode；未找到 MSI 注册时禁用入口并提示便携版处理方式。
- 当前 EXE 复制到 `%TEMP%` 作为短生命周期卸载 helper，主程序退出后由 helper 调用 Windows Installer。
- 默认分支只卸载程序；数据清理分支同时受 UI 二次确认、Rust 短语校验和当前用户默认数据根目录校验约束。
- 单元测试覆盖确认短语、跨用户/伪装路径拒绝和 ProductCode 规范化；schema v10 smoke/audit 覆盖 UpgradeCode 绑定、Windows Installer API、命令参数和 UI 确认短语 authoring。
- 为避免破坏当前开发机，自动 smoke 不实际卸载已安装产品；隔离环境只需补最小安装、升级、保留数据卸载和明确清理流程，不再要求完整 Windows Installer 故障矩阵。

### 6.6 签名发布与安全自动更新

签名构建：

- `build.bat --package --sign` 要求当前用户证书指纹或 PFX、Code Signing EKU、HTTPS RFC 3161 时间戳和 HTTPS stable 更新清单地址。
- PFX 密码只从环境变量读取；脚本通过 .NET X509Store 暂存证书，`signtool` 命令行只接收 SHA-1 查找指纹，不接收密码，结束后删除本轮新增的证书项。
- EXE 在进入便携 ZIP 和 MSI 前签名，MSI 生成后再签名；两者均执行 `signtool verify /pa /all`。
- 签名发布生成 `update-manifest.json` 和 detached CMS/PKCS#7 `update-manifest.json.p7s`，并在 release manifest 记录 signed、signerSha256、timestampUrl、updateFeedUrl 和清单文件名。
- 手动 `signed-release` CI 工作流绑定受保护 environment，从 secret 写出短生命周期 PFX，完成打包、smoke、签名更新集成和 audit 后清理 PFX 并上传包。

客户端更新：

- 启动时检查默认关闭；只有用户明确开启、构建已配置签名更新源且检测到本产品 MSI 注册时才真正启用；`--skip-update-check` 用于隔离测试。
- 清单和 `.p7s` 使用 256 KiB 上限，MSI 使用 200 MiB 上限；所有最终重定向地址仍必须是无凭据 HTTPS。
- 清单限定 product=`StockIpoReminder`、channel=`stable`、schema v1、严格递增版本、最低 Windows Build、MSI 大小/哈希和固定签名证书；最低 Build 使用不受应用 manifest 兼容性虚拟化影响的 `RtlGetVersion` 读取。
- MSI 下载采用流式 SHA-256 和声明大小双重校验；下载完成和 helper 启动前都执行 Authenticode 系统信任与相同证书指纹复核。
- helper 等待父进程退出并给 Watchdog 收尾时间，再以 `/i ... /passive /norestart` 安装；结果写入 `diagnostics/update-last-result.json`。
- 0.3.1 临时集成报告已验证 Authenticode 文件签名、detached CMS、证书固定、MSI 哈希和篡改清单拒绝；由于未使用正式 CA，自测只接受精确的不受信测试根状态，生产系统信任仍未验收。

### 6.7 用户同意的脱敏崩溃报告

- 默认关闭。只有构建同时提供 `STOCK_IPO_CRASH_REPORT_URL` 和 `STOCK_IPO_CRASH_REPORT_PRIVACY_URL`，且两者都是绝对、无凭据 HTTPS URL 时，设置页才允许启用自动发送或明确点击发送。
- 自动发送不是静默默认行为；用户保存开启设置后，下一次启动只尝试发送一份尚未成功发送的报告。`--skip-crash-upload` 用于发布 smoke 和其他隔离测试。
- 客户端只扫描当前数据根目录的 `diagnostics/crashes` 顶层，只接受名称为 `crash-recovery-*.json`、非空且不超过 128 KiB 的普通文件；数据库、日志、公告正文和原始接口响应不进入上传选择范围。
- 上传前递归移除命令行、参数、路径、目录、用户名、主机、设备、账户、持仓、Cookie、Authorization、token、密码、secret 和 credential 等敏感键；其余字符串继续经过 `operations::redact`，数组与文本长度也有边界。
- HTTP 客户端总超时 30 秒并使用 `Policy::none()` 禁止重定向；过去滚动 24 小时最多记录 3 次尝试，失败也计数，避免无界后台重试。
- 成功报告的 SHA-256 单独保留并去重；尝试状态最多保留 100 条/30 天，成功哈希最多保留 500 个。本地状态位于 `diagnostics/crash-upload-state.json` 和 `diagnostics/crash-upload-last-result.json`。
- 当前 0.3.1 本机发布未嵌入接收端或隐私政策，release manifest 明确将两个字段记录为 null，因此不会发生真实外部上传。
- 客户端完成不等于服务上线。正式接收服务的请求认证、载荷 schema 校验、滥用防护、访问审计、数据驻留、保留期限、用户删除渠道和隐私政策仍必须在外部部署前完成。

### 6.8 第二通知通道

- 设置页可选择企业微信机器人、钉钉机器人、飞书机器人或 PushPlus，保存秘密输入、发送用户主动测试，并单独清除凭据；功能和设置均默认关闭。
- 企业微信仅接受 `qyapi.weixin.qq.com/cgi-bin/webhook/send` 且必须有 `key`；钉钉仅接受 `oapi.dingtalk.com/robot/send` 且必须有 `access_token`；飞书仅接受 `open.feishu.cn` 或 `open.larksuite.com` 的 `/open-apis/bot/v2/hook/` 路径；PushPlus 固定发送到 `https://www.pushplus.plus/send`。
- 凭据保存到 `secrets/secondary-notification.dpapi.json`，使用 Windows DPAPI 当前用户范围、禁止交互 UI，并附加产品专用 entropy；复制到其他用户或设备后不能解密。
- 远程内容只包含产品名、公开的新股简称和申购代码、提醒类型、本地到期时间、脱敏摘要与“不自动下单”边界，不发送数据库、日志、公告正文、用户/设备标识、券商信息或凭据。
- HTTP 客户端禁止重定向，总超时 15 秒，响应上限 64 KiB；HTTP 状态成功后仍校验服务商 JSON 成功代码，错误只保留脱敏摘要。
- 本地提醒进入投递租约时建立独立第二通知 Outbox 项；远程租约为 2 分钟，进程退出后可恢复，失败按 1、5、15、30 分钟退避，第 5 次失败后进入 Exhausted 并停止自动重试。
- 自动批次与发送测试共享滚动 1 小时 20 个批次配额，并在联网前预留；请求尝试保留 30 天且最多 2,000 条，Delivered、Cancelled、Exhausted 终态队列保留 90 天。
- 设置页显示待发送、重试、耗尽、最近成功和脱敏错误；关闭通道或切换服务商会取消旧服务商未完成项。
- 详细安全、凭据、消息内容和后续边界见 `docs/secondary-notifications.md`。

## 7. 剩余事项的统一判断

0.3.1 的代码、自动化测试、打包、启动减负和 PDF 链路减重已经闭环。后续不再把所有可想象的环境都列为“必须”，只验证一个本地提醒工具真正依赖的主路径。

### 7.1 当前必须完成：核心提醒实机闭环

以下 5 项直接影响当前用户日常使用，属于唯一的必做队列：

1. **真实数据目录启动（已完成）**：用户已确认使用当前真实数据目录启动速度正常，不再发生约 8 秒无反馈；数据库后台准备期间界面可见且不会读取错误默认值。
2. **真实提醒投递（已完成）**：用户已确认实际提醒、提示窗、声音、任务栏闪烁等当前启用通道均正常。只保留现有自动化回归，不做所有系统策略组合。
3. **真实恢复补做**：完成一次睡眠或锁屏后恢复，并覆盖一次网络断开后恢复，确认到期提醒不会丢失、不会重复轰炸，恢复后同步能够继续。RDP、热插拔和长时间恢复风暴不属于本项。
4. **发布候选联网同步**：每次准备交付新版本时，用隔离数据目录执行一次真实同步，确认必要来源结论、数量审计和公告元数据链接正常；来源不完整时必须继续显示降级状态，不能误报“今日无新股”。
5. **MSI 最小生命周期**：只在隔离 Windows 环境完成一次安装、启动、从上一可分发版本升级、普通卸载保留数据，以及明确确认后的当前用户数据清理。完整回滚、修复、UAC 拒绝、重启码和所有 Windows Installer 故障排列不作为当前完成条件。

完成这 5 项后，当前产品即可视为“Windows 11 日常使用闭环”。第 1、2 项已由用户确认，第 4 项已由 schema v2 联网同步报告覆盖；当前只剩第 3 项恢复补做和第 5 项 MSI 最小生命周期。

### 7.2 可以继续优化，但不阻塞当前使用

1. **设置页继续简化（已完成）**：第二通知、自动更新和崩溃报告已收纳到默认折叠的“高级可选功能”；未配置状态使用普通说明色，不制造告警，启动时自动检查更新对新安装默认关闭。
2. **资源预算继续观察**：保持窗口/托盘先出现、空闲 Private Bytes 低于 100 MiB、同步不产生意外子进程、不新增 PDF；只有重新出现真实退化时才继续做性能专项。
3. **数据目录保持有界**：继续保留 7 份备份、14 天日志和有界 Outbox；历史 PDF 由用户自行处理，不增加自动清理，也不再增加正文缓存。
4. **编译警告顺手清理（已完成）**：删除确认无调用的包装接口和 UI 不读取的查询字段，将测试辅助入口限制在测试构建；test、dev check、release 和 WiX 当前均为 0 warning。
5. **上游契约维护**：来源改版时修复真实故障并更新 fixture；不建设独立监控服务、采集服务或通用爬虫平台。

### 7.3 只有满足条件时才需要

- **正式公开分发**：只有面向不受控外部用户发布时，才需要正式 CA Code Signing、真实 RFC 3161 时间戳、SmartScreen/安全软件验收、受保护签名环境和 HTTPS stable 更新源；当前个人/内部使用不以此为阻塞项。
- **自动更新上线**：只有实际部署签名更新源后，才补在线升级、断网、篡改拒绝和失败回滚；未配置源和证书时继续关闭。
- **崩溃报告上线**：只有决定运营正式接收服务时，才需要隐私政策、服务端校验、限流、审计、保留和删除治理；当前上传保持关闭。
- **第二通知通道**：只对用户实际启用的服务商做一次真实账号端到端测试，不要求同时购买或配置企业微信、钉钉、飞书和 PushPlus 四套账号。
- **额外 Windows 环境**：只有正式承诺 Windows 10、RDP 或多屏混合 DPI 支持，或用户确实在这些环境使用时，才补对应 smoke；当前正式验证范围保持 Windows 11 x64。

### 7.4 当前停止投入

- 不再执行磁盘满、备份目录只读、代理篡改时间、无交互桌面、完整通知策略组合等极端矩阵；现有自动化失败边界已经足够。
- 不再把 Watchdog 在注销、关机或监督进程与主进程同时被杀后的继续恢复作为目标；用户态程序无法保证在所有进程均不存在时自我恢复。
- 不做 2,000 条真实滚动压力、全套键盘/无障碍认证、任务栏位于所有边缘、显示器热插拔和长时间恢复风暴；出现实际问题再定向修复。
- 不做完整 MSI 回滚、修复、UAC 拒绝、重启码和全部失败排列；保留第 7.1 节的最小安全生命周期即可。
- 邮件、短信、任意自建 Webhook、多设备同步、独立采集服务、服务端推送、中心账号体系和设备注册继续暂停，只保留状态记录。
- 扫描 PDF OCR、图像识别、版面理解、PDF 按页/按对象解析、外部低内存解析器和任何新的自动公告正文提取方案永久排除。
